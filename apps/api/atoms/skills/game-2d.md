# 2D 游戏制作指导

使用 React + TypeScript 组织游戏界面与状态，一次返回完整的多文件 JSON 源码（不调用外部工具或构建脚本）。棋盘、卡牌和界面驱动的玩法可用 DOM。需要连续绘制、滚动镜头或较多运动对象时使用 Canvas 2D。React 管理菜单、HUD 和控制界面，规则和状态由独立模块管理。适配不同屏幕时保持视觉与输入坐标一致。使用平台提供的依赖与本地资源。

### 平台关卡的可达性

有跳跃和平台时，先确定起跳速度、重力、空中横移和碰撞规则，再摆放平台。以角色脚底和平台的实际碰撞面为准。恒定重力下可用 `v² / (2g)` 估算理论跳高，落点仍要按实际时间步、下降时的横向位置、角色碰撞体和头顶障碍检查。必经跳跃要留出高度和横向落点余量，首跳应有清楚的起跳位置和足够宽的落点。

布置关卡时给首个必经平台、关键道具和出口留出可达路线。已有跳跃方式够不到时，调整跳跃参数或添加可用的过渡路线。用户明确要求平台跳跃或可通关路线时，用实际碰撞与输入逻辑自测对应路径。
