# 2D 游戏制作指导

参考项目内 `web-artifacts-builder` 的 React 组件与本地构建组织。棋盘、卡牌和界面驱动的玩法可用 DOM。需要连续绘制、滚动镜头或较多运动对象时使用 Canvas 2D。React 管理菜单、HUD 和控制界面，规则和状态由独立模块管理。适配不同屏幕时保持视觉与输入坐标一致。使用平台提供的依赖与本地资源。

### 平台关卡的可达性

有跳跃和平台时，先确定起跳速度、重力、空中横移和碰撞规则，再摆放平台。以角色脚底和平台的实际碰撞面为准。恒定重力下可用 `v² / (2g)` 估算理论跳高，落点仍要按实际时间步、下降时的横向位置、角色碰撞体和头顶障碍检查。必经跳跃要留出高度和横向落点余量，首跳应有清楚的起跳位置和足够宽的落点。

逐关从出生点检查至少一条能完成目标的路径，包括首个必经平台、必须击败的敌人、必拿道具、开关和出口。已有跳跃方式够不到时，调整跳跃参数或添加实际可用的过渡路线。改了物理、平台布局或目标位置后重查。验证用游戏真实更新逻辑和正常输入，确认角色在目标平台上落地并能继续推进。
