# 构建失败后的恢复（2026-11-12）

## 交付检查与自动修复

网站、游戏和幻灯片通过构建、启动和主要操作短测后保存。构建或运行错误由后台自动修复，首稿之外最多 3 轮。候选和同一错误都重复时提前停止。游戏源码审查发现具体缺陷或演示的下一页按钮无响应时，最多做一次限时质量修复并复验。无进展或修复引入硬故障时交付此前能运行的候选。视频在生成服务完成后直接保存。

任务进行期间界面统一显示「建设中」。校验服务暂不可用时先复查同一候选，复查无需模型调用。模型调用按实际用量结算。

达到修复上限、额度不足、执行超时或服务故障无法恢复时保留候选。继续修复时优先复验现有候选并恢复任务计划。

## 兼容性修正

- 补齐 `cite`、`q`、`kbd`、`ruby` 等标准文本标签，继续使用已有属性和 URL 校验。
- CSS 根据解析后的属性名和函数名检查主动内容。合法的 `scroll-behavior` 可直接使用。
- 模型把约定的文件写在 JSON 顶层时，仅在 `files` 内缺少同名文件且顶层值是字符串时移入。校验和保存使用整理后的产物，无法确定如何修复的字段会返回具体位置。需要模型修复时沿用现有调用预算。
- 后续重试成功后，原失败消息显示「这次构建已修复」。截图中的候选已重新通过隔离浏览器检查并保存为 v1，本次恢复新增模型调用和扣费均为零。

## 失败候选保留与继续修复

这次修正针对真实生成时的两项问题：正常 input.list 被拒绝，以及失败后仅显示技术报错、要求用户手工重提需求。

- 生成提示与编译器共同读取 shared/contracts/html-policy.json，补齐 list、表单提示、meter 等常见安全属性。脚本、事件属性、外链和嵌入限制继续由编译器与沙箱执行。
- HTML 检查聚合最多 20 项诊断，一次反馈给自动修复，减少每次只修一个问题的往返。
- 迁移 0003 新增 run_candidates 和 runs.retry_of_run_id；不修改现有项目、版本和积分账本。
- 模型返回后先保存构建内容。校验失败或校验服务不可用时保留内容及诊断；成功则在交付事务内删除本轮临时候选。
- 用户点击“继续修复”创建关联的新任务，沿用原始需求、基础版本、候选内容和诊断。先重新检查候选，通过就直接交付，不发模型请求、不产生本轮模型积分消费。
- 仍需修复时带着具体内容调用模型，继续使用原来的预授权、用量结算与异常冻结规则。
- 继续入口受访客、项目、终态、当前基础版本和幂等校验保护；旧执行者无法改写已终止候选。
- 页面显示可操作的失败卡片，提供继续修复/重新生成、调整需求和折叠诊断。已有版本和数据保留，重新调用 AI 的计费规则在按钮下说明。

兼容边界：升级前失败的记录没有保存模型候选内容，不能还原丢失的代码。页面为这些记录提供“重新生成”，自动携带原需求及旧诊断；升级后的失败可继续使用保留内容。

验证：API 27 项、编译器 10 项通过；两条完整浏览器流程通过，其中新增流程覆盖失败后刷新、继续修复、datalist 交互和积分结算。额外 API 测试验证了重新检查直接交付时无模型调用、零余额可完成纯校验，以及过期候选和跨项目请求被拒绝。
